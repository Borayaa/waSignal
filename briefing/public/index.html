From chat message to order

How a signal posted in a WhatsApp chat or Telegram channel becomes a buy or sell order on your cTrader account, and every check it has to pass on the way.

~1 sto extract the trade
~1 sto place the order

Timings are typical, not guaranteed. Automation ships switched off and in dry-run mode: nothing is traded until you turn it on.

The path of one message

A message only becomes an order if it survives every step. Anything that fails stops there and is logged with the reason.

Five stages, in order

  1. Sources and the bridge

    One small program, the bridge, runs on a VPS or home server and listens to both WhatsApp and Telegram. It forwards messages from only the one chat you picked for each source.

    Deep dive
    • WhatsApp: uses Baileys, which signs in like WhatsApp Web (you scan a QR code).
    • Telegram: signs in as your own user account over MTProto (GramJS), so it can read channels and groups you have joined. It may ask for your 2FA password.
    • Polling: the bridge asks the Worker for its instructions every 3 seconds: which accounts should be connected and which chat is the target.
    • Filtering: messages from any other chat are dropped, and empty messages (no text) are skipped.

  2. Intake

    The bridge posts each message to the Worker. The Worker double-checks the chat, queues the message, and processes messages one at a time.

    Deep dive
    • Endpoint: POST /api/bridge/message, protected by a bearer token.
    • Target-chat check: the chat id must match the target chosen for that source (WhatsApp or Telegram). Otherwise the answer is "ignored".
    • Queue: accepted messages go into a Cloudflare Queue. The consumer handles one message at a time and has no short time limit, so extraction plus a broker session can finish.
    • Duplicates: each message id is stored once. If the same id arrives again it is ignored.

  3. Extraction with Clairic

    An AI model on Cloudflare Workers AI (Clairic) reads the text and fills in a fixed set of fields, each with a confidence score. It reads; it does not invent.

    Deep dive
    • Fields: action (BUY/SELL, LONG and SHORT count), order type (limit, stop, now, market), symbol, entry price (and upper end of a range), stop loss price, stop loss in pips, take-profit prices, take-profit pips, lot size, and entry time window (start and end).
    • Normalising: LONG becomes BUY and SHORT becomes SELL. Times like 20.10 become 20:10.
    • Pending orders: a limit or stop order without an entry price stays pending, so it is rejected later. It is never turned into a market order.
    • Every number must appear in the message. A price the model returns that is not written in the text is dropped, and the signal is rejected as a misread.
    • Pips need a unit. A pip value is only accepted when written next to "pips", "points" or "pts". A pip value echoed into a price field is discarded.
    • Is it a signal? Only if a side and a symbol are found (see the default symbol below). Confidence is the lower of the side and symbol scores.

  4. Decision: the safety checks

    Plain code, not AI, decides whether the extracted trade is allowed. This is where most bad messages are stopped. The full list is in the safety rules table.

    Deep dive
    • Symbol: if the message names none, your default symbol is used. Aliases are mapped (GOLD to XAUUSD), checked against an allow-list, and your broker suffix is added.
    • Pips to prices: pip distances are converted using a per-symbol pip size (gold is 0.1, so 25 pips is 2.5). This needs an entry price.
    • Time window: a window like 20.10-23.20 is read in your account timezone and becomes the pending order's expiry. A window that has already passed is rejected.
    • Sanity: confidence threshold, stop loss required, SL and TP on the correct side of entry, TP on the profit side of SL, messages older than 5 minutes ignored, max open positions.
    • Sizing: lot is fixed, or taken from the signal, capped at your max lot and rounded to 0.01. Take-profit strategy: first, last, or split into one position per TP with the lot divided evenly.
    • Dry run: if on, a valid trade is built and logged but never sent.

  5. Execution on cTrader (IC Markets)

    The Worker opens a JSON WebSocket to cTrader's Open API, finds the symbol, converts lots to volume, and sends the order to your IC Markets account.

    Deep dive
    • Connection: wss://demo.ctraderapi.com:5036 or live.ctraderapi.com:5036, authorised with an OAuth token that refreshes automatically.
    • Market orders: cTrader does not accept absolute SL/TP on market orders. So the Worker takes a spot quote (ask for BUY, bid for SELL), sends relative SL/TP, waits for the fill, then amends the position to the exact SL/TP prices.
    • Limit and stop orders: sent with absolute SL/TP. If there is an entry window, the order is good till date and expires at the end of it.
    • Record: each order request and response is stored in D1 and shown in the dashboard, including failures. Status ends as executed, partial or failed.

Messages that are stopped

BUY LIMIT GOLD SL 2330 TP 2360
Rejected

A limit order needs an entry price. It stays a pending order with no entry and is refused, never turned into a market order.

Sell now SL 25 pips TP 60 pips
Rejected

Pips are distances from an entry price, and the message has none. Without an entry, the pips cannot become prices.

Message says "SL 2318"; model returns SL 2381
Rejected

Misread price: 2381 is not written anywhere in the message, so it is dropped and the signal is refused rather than guessed.

Expected value: is a strategy worth following?

Expected value (EV) is what a strategy earns on average per trade after costs. A high win rate means nothing by itself: winning 80% of trades still loses money if the average loss is much bigger than the average win. What matters is the win rate together with the risk-to-reward ratio. Try your own numbers below.

Glossary

Stop loss (SL)
A price at which the trade closes automatically to cap your loss.
Take profit (TP)
A price at which the trade closes automatically to lock in a gain.
Lot
The trade size. 0.01 lot is the smallest step here; what a lot is worth depends on the instrument.
Pip
A small price unit. Its size depends on the instrument: 0.0001 for most pairs, 0.01 for JPY pairs, 0.1 for gold in this setup.
R multiple
Profit or loss measured in units of your initial risk. Risk 25 pips and make 50: that is +2R.
Spread
The gap between the buy price (ask) and sell price (bid). It is a cost on every trade; buys fill at the ask, sells at the bid.
Market order
Fills now at the current price.
Limit order
Waits for a better price: buy below the market or sell above it.
Stop order
Waits for the price to move through a level: buy above the market or sell below it.
GTD expiry
Good till date: a pending order is cancelled automatically at a set time, here the end of the entry window.
